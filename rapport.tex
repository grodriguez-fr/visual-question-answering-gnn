\section{Introduction et Analyse du Tutoriel Initial}

\subsection{La Tâche : Visual Question Answering (VQA)}
Le projet étudié porte sur le Visual Question Answering (VQA) appliqué au dataset CLEVR. L'objectif est de concevoir un système capable de répondre à des questions complexes nécessitant un raisonnement logique et spatial sur des images synthétiques contenant des formes géométriques simples. Contrairement aux approches classiques basées sur des CNNs pour l'image et des RNNs pour le texte, l'approche étudiée ici modélise les données sous forme de graphes pour capturer explicitement les relations entre les objets et les concepts linguistiques.

\subsection{Analyse du Workflow de Données MGN}
L'architecture MGN repose sur un pipeline de traitement séquentiel qui transforme les données brutes en un programme exécutable. Voici le détail étape par étape du flux de données :

\begin{enumerate}
    \item \textbf{Entrées (Question et Scène) :} 
    Le système prend en entrée une question en langage naturel. Pour la partie visuelle, contrairement à ce que suggère une approche multimodale classique, le modèle ingère une \textbf{description de scène structurée au format JSON} (Vérité Terrain) et non une image brute. Cela permet de contourner l'étape d'extraction visuelle (CNN).

    \item \textbf{Graph Parser (Construction des Graphes) :} 
    Un module de parsing convertit ces entrées structurées en deux graphes distincts :
    \begin{itemize}
        \item Le \textit{Graphe de Question} est construit via des règles syntaxiques (ex: spaCy), où les nœuds sont les mots et les arêtes représentent les dépendances grammaticales.
        \item Le \textit{Graphe de Scène} encode les objets du JSON. Point crucial : plutôt que d'encoder explicitement les relations spatiales (ex: "à gauche de") sous forme d'arêtes, le modèle intègre directement les \textbf{coordonnées 3D brutes $(x, y, z)$} dans les attributs de chaque nœud objet. C'est au réseau d'apprendre implicitement la géométrie de la scène.
    \end{itemize}

    \item \textbf{Graph Matcher (Appariement) :} 
    Les deux graphes sont transformés en embeddings. Un module d'appariement (souvent un GNN partagé ou un MLP) calcule ensuite une matrice de correspondance (attention soft) entre les nœuds textuels et les nœuds objets, cherchant à aligner les mots avec les objets correspondants.

    \item \textbf{Générateur de Programme (Seq2Seq) :} 
    Un décodeur RNN (Seq2Seq) utilise ces représentations pour générer séquentiellement un \textbf{programme symbolique} (une suite de tokens logiques comme \texttt{filter\_shape[cube], query\_color}). C'est sur cette séquence que s'effectue l'entraînement supervisé (calcul de la Loss entre le programme généré et le programme attendu).

    \item \textbf{Exécuteur Symbolique :} 
    La réponse finale n'est pas produite par le réseau de neurones. Un exécuteur algorithmique déterministe prend le programme généré par le modèle et l'applique sur le JSON de la scène pour "calculer" la réponse. Le raisonnement logique pur est donc délégué à ce moteur de règles externes.
\end{enumerate}

\subsection{Observations et Limitations}
L'analyse du papier, du code et des reviews soulève plusieurs questions méthodologiques.

\subsubsection{Utilisation des Annotations de Vérité Terrain}
Le code utilise directement les annotations JSON de vérité terrain plutôt que d'extraire les features visuelles des images via Mask R-CNN. Le modèle ne traite jamais les pixels bruts, mais lit une description structurée parfaite de la scène. Cette approche diffère des méthodes comparées (MAC, FiLM, Relation Networks) qui travaillent sur les images brutes avec leur bruit visuel inhérent. Le Reviewer 3 a noté : \textit{"This becomes a trivial problem of semantic matching of labels and does not necessitate the complex graph fusion that is proposed"}. Sans la difficulté de la perception visuelle, la tâche se rapproche d'un appariement sémantique entre tokens de question et labels JSON.

\subsubsection{Spécificité au Dataset CLEVR}
L'évaluation porte exclusivement sur CLEVR et ses variantes (CLOSURE). Le système repose sur un exécuteur symbolique et des parsers de graphes spécifiquement conçus pour la structure CLEVR. L'adaptation à d'autres datasets (VQA v2, GQA) nécessiterait de réécrire l'exécuteur et les règles de parsing, pas seulement de réentraîner les poids. Notre modification "Classification End-to-End" vise à tester le modèle sans l'exécuteur symbolique, permettant d'évaluer les capacités réelles du GNN.

\subsubsection{Architecture GNN Partagée}
Le modèle original utilise un GNN partagé pour traiter les deux graphes (question et scène). Ces modalités sont hétérogènes : syntaxe linguistique abstraite d'un côté, propriétés physiques et coordonnées 3D de l'autre. Il nous semble que traiter ces deux types de graphes avec les mêmes poids pourrait ne pas être optimal, mais nous ne sommes pas certains de l'impact réel de cette approche. Notre architecture Two-Stream propose de séparer ces traitements pour tester cette hypothèse et observer si la spécialisation de chaque flux apporte un bénéfice avant fusion.


\subsection{Mise à jour du code}
 Avant d'entreprendre nos modifications, nous avons dû moderniser le code, initialement conçu pour des versions obsolètes de PyTorch. Nous avons porté l'ensemble du projet sur un environnement \textbf{PyTorch 2.9.1 avec CUDA 12.6}. Cette version modernisée constitue notre \textbf{Baseline} pour les expériences suivantes, garantissant la reproductibilité des résultats sur du matériel actuel.

\section{Modifications Architecturales et Fonctionnelles}

Pour dépasser les limitations identifiées et explorer le potentiel des GNNs, nous avons implémenté trois modifications structurelles majeures par rapport à la baseline.

\subsection{Axe 1 : Architecture Disjointe (Two-Stream)}
\textbf{Observation :} Le modèle original utilise un GNN partagé pour traiter simultanément les deux graphes hétérogènes (question linguistique et scène spatiale). Nous nous sommes demandé si une fusion précoce pourrait introduire du bruit et si traiter chaque modalité indépendamment avant fusion pourrait être bénéfique.

\textbf{Modification :} Nous avons testé une architecture "Two-Stream" où les encodeurs de graphe de scène et de question sont séparés dans les premières couches. Chaque branche traite ses propres représentations avant une fusion tardive, permettant potentiellement de mieux préserver la spécificité de chaque modalité.

\subsection{Axe 2 : Explicabilité via Graph Attention Networks (GAT)}
\textbf{Motivation :} Les couches GNN standards agrègent l'information des voisins sans fournir d'information sur l'importance relative de chaque connexion. Pour mieux comprendre le raisonnement du modèle et identifier sur quels objets il se concentre, nous avons souhaité introduire un mécanisme d'attention visualisable.

\textbf{Modification :} Nous avons remplacé les couches GNN par des couches \textbf{GAT (Graph Attention Networks)} qui apprennent des poids d'attention dynamiques $\alpha_{ij}$ pour chaque arête.
\begin{equation}
    \alpha_{ij} = \frac{\exp(\text{LeakyReLU}(\vec{a}^T [W\vec{h}_i || W\vec{h}_j]))}{\sum_{k \in \mathcal{N}_i} \exp(\text{LeakyReLU}(\vec{a}^T [W\vec{h}_i || W\vec{h}_k]))}
\end{equation}
Cette modification nous permet d'extraire les coefficients d'attention et de visualiser quels objets (nœuds) sont les plus "importants" pour le modèle lors du traitement d'une question donnée.

\subsection{Axe 3 : Changement de Tâche (Classification End-to-End)}
\textbf{Problème :} La tâche originale de génération de programme délègue le raisonnement final à un exécuteur symbolique externe qui a accès à la vérité terrain parfaite. Cela ne teste pas la capacité du réseau de neurones à "voir" et "comprendre" la scène pour répondre.

\textbf{Modification :} Nous avons transformé le pipeline pour effectuer une véritable tâche de VQA (Classification). Nous avons ajouté une tête de classification (MLP) en sortie du module de fusion. Le modèle doit désormais prédire directement la réponse finale (ex: "bleu", "oui", "cube") parmi un vocabulaire fixe, forçant le GNN à encoder toute l'information nécessaire à la réponse dans ses vecteurs latents.

\section{Résultats et Analyse}

\subsection{Protocole Expérimental}
Tous les modèles sont entraînés sur \textbf{2000 questions CLEVR} (1600 train, 400 validation) pendant \textbf{20 epochs}.

\subsection{Analyse}

\textbf{Baseline (99\%) :} L'approche neuro-symbolique originale obtient d'excellentes performances car l'exécuteur symbolique effectue le raisonnement logique à partir du JSON de vérité terrain. Le modèle génère simplement une séquence syntaxiquement correcte.

\textbf{Two-Stream (98.5\%) :} La séparation des GNN ($\psi_1$ pour questions, $\psi_2$ pour scènes) ne montre aucun avantage dans ce contexte où l'exécuteur fait le travail final. Les courbes d'entraînement sont identiques à la baseline.

\textbf{GAT + XAI (97.5\%) :} Le remplacement par des couches GAT permet d'extraire les poids d'attention et de visualiser les nœuds importants. La baisse de 1.5 points est un compromis acceptable pour l'explicabilité. Les visualisations confirment que le modèle se focalise sur les objets pertinents de la scène.

\textbf{Classification End-to-End (44\%) :} En supprimant l'exécuteur et en forçant le modèle à prédire directement parmi 30 classes de réponses, la performance chute drastiquement. Le modèle surapprentit et généralise mal.

\textbf{Hypothèse critique :} Cette chute de performance (99\% → 44\%) suggère que la "généralisation" apparente du modèle original est biaisée par l'exécuteur symbolique. L'exécuteur a accès au JSON parfait et applique des règles déterministes, tandis que le réseau de neurones n'a qu'à générer des tokens syntaxiquement corrects. En mode classification pure, le GNN doit effectuer le raisonnement complet, révélant ses limites réelles.

\subsection{Explicabilité (XAI)}
Les poids d'attention extraits des GAT permettent de visualiser les nœuds sur lesquels le modèle se concentre. Les visualisations montrent que le modèle focalise son attention sur les objets pertinents de la scène, validant le mécanisme d'attention.

\section{Conclusion}
Ce projet a permis de reproduire et d'analyser l'approche MGN sur un dataset réduit (2000 questions). La modernisation du code sur PyTorch 2.9.1 a constitué la baseline nécessaire aux expérimentations.

Les modifications architecturales (Two-Stream, GAT) n'ont pas apporté d'amélioration significative en mode génération de programme : la baseline atteint 99\%, le Two-Stream 98.5\%, et le GAT 97.5\%. Ces résultats montrent que dans ce contexte neuro-symbolique, où l'exécuteur effectue le raisonnement logique final, la sophistication du GNN importe peu.

Le résultat le plus révélateur provient du mode classification end-to-end (44\% d'accuracy), qui force le modèle à raisonner sans l'aide de l'exécuteur symbolique. Cette chute de performance (99\% → 44\%) soulève des questions sur la nature réelle de la "généralisation" observée dans les approches neuro-symboliques. L'exécuteur, ayant accès au JSON parfait et appliquant des règles déterministes, effectue possiblement l'essentiel du raisonnement, masquant ainsi les limites du modèle neuronal.

Les mécanismes d'attention du GAT ont néanmoins permis d'extraire des visualisations utiles pour l'explicabilité, confirmant que le modèle focalise son attention sur les objets pertinents. L'analyse a également révélé que le modèle apprend les relations spatiales implicitement via les coordonnées 3D brutes, sans nécessiter d'encodage symbolique explicite.

Ces résultats illustrent les défis de l'évaluation des systèmes hybrides neuro-symboliques et suggèrent que des benchmarks sur des tâches purement neuronales (sans exécuteur) seraient nécessaires pour évaluer correctement les capacités de généralisation des GNNs en VQA.
